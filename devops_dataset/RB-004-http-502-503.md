# HTTP 502/503 Troubleshooting Runbook

**Last Updated:** 2026-08-28  
**Owner:** Platform Engineering

## Purpose
Troubleshoot HTTP 502 Bad Gateway and HTTP 503 Service Unavailable responses.

## Overview
502 usually indicates an upstream communication/response problem. 503 commonly indicates no healthy upstream or no ready Kubernetes endpoints.

## Investigation
Identify the layer generating the response. Correlate NGINX error logs, API Gateway logs, Service/EndpointSlice state, readiness probes, and downstream dependencies.
```text
NGINX error:
upstream prematurely closed connection
upstream=api-gateway.nexora-prod.svc.cluster.local:8080
```
For 503, check whether ready endpoints are zero. For 502, check DNS, TCP connectivity, ports, and upstream process health.

## Resolution / Verification
Validate gateway-to-service and in-cluster requests, then monitor 5xx rate and latency until normal.

## Example Errors
```text
ERROR service-operation
status=failed
environment=nexora-prod
action=inspect-metrics-and-logs
```
